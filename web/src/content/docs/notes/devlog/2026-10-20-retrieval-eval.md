## 3. 과정

### Day 1 (10/20) 질의 번역 단계

#### 번역 단계 만들기

- `fabatlas/translate.py`: 한국어 질문을 영어 검색 질의로 번역해요. 번역할 때마다 원문, 번역, 지연(ms)을 `logs/translate.jsonl`에 남겨요(gitignore 대상).
- `fabatlas/prompts.py`: 번역 프롬프트를 분리했어요. 규칙은 "반도체 공정 용어는 업계 표준 영어 용어로 옮겨요"와 "영어 질의 한 줄만 출력해요" 두 줄이에요.
- `fabatlas/bm25.py`: 한국어 질문 → 번역 → BM25 경로예요. dense 검색(bge-m3)은 번역 없이 한국어 질문을 그대로 써요([D-011](/fab-atlas/notes/decisions/#d-011--bm25-축-전용-질의-번역)).
- `fabatlas/llm.py`: 답변과 번역이 같은 호출 함수(`complete`)를 써서 모델 스냅샷(`gpt-4.1-mini-2025-04-14`)과 온도(0)가 같아요.

```python
from fabatlas.translate import translate_query
tr = translate_query("웨이퍼 테스트에서 프로브 카드는 어떤 역할을 하나요?")
tr.query        # 'What is the role of a probe card in wafer testing?'
tr.latency_ms   # 지연(ms)
```

### Day 2 (10/24) 평가셋

#### 형식: `data/eval/qa_v1.jsonl`

한 줄에 한 문항이에요. 필드는 id, question, type(일반/용어변형/답없음), process, level, answer, evidence, variant_group, drafted_by, note예요. 필드 설명과 라이선스는 [data/eval/README.md](https://github.com/Kyoo32/fab-atlas/blob/main/data/eval/README.md)에 있어요.

- evidence는 `{doc_id, char_start, char_end, quote}` 목록이고, quote는 원문 앞 80자예요. 청킹 방식이 바뀌어도 정답이 유지돼요.
- 라이선스: 질문·정답은 MIT, quote는 위키백과 발췌라 CC BY-SA 4.0이에요.

#### 도구: `scripts/eval_tool.py`

```bash
uv run python scripts/eval_tool.py find "die sort"              # data/raw 단순 문자열 검색
uv run python scripts/eval_tool.py draft --process 포토 --n 3   # 근거 후보 구절 + 초안 틀 (--doc S011도 가능)
uv run python scripts/eval_tool.py add                          # 대화형으로 한 문항 추가
uv run python scripts/eval_tool.py add --json '{...}'           # 초안 한 줄 추가
uv run python scripts/eval_tool.py check                        # 검사와 요약
```

- 테스트 대상 검색기(bge-m3, BM25)는 쓰지 않아요. `find`는 소문자 문자열 포함 검색이에요.
- `draft`는 근거 후보 구절을 고르고 위치를 채운 틀만 만들어요. 인과 표현(because, thus, prevent 등)이 있는 2\~3문장 구절을 앞에 두고, 문서를 번갈아 골라요. 역사·어원 섹션은 뒤로 보내요. 평가셋에 이미 있는 근거와 겹치는 구절은 건너뛰어요.
- 질문·정답 문장은 테스트 대상 답변 모델(gpt-4.1-mini)에게 맡기지 않아요. 초안은 Claude가 대화에서 쓰고 `drafted_by=claude`로 넣어요. 내가 내 말로 고친 뒤 `kyoo`로 바꿔요.
- `check`가 보는 것: quote와 원문 위치 일치, type·공정·level별 개수와 부족분, 인과 질문 수, 용어변형 묶음의 근거 일치, 답없음 문항의 근거 없음, 질문 속 영어 단어·약어가 근거에 그대로 있는지(원문 베낌 의심), drafted_by=claude 남은 수

#### 문항 구성 (목표 50)

| 구분 | 목표 | 메모 |
| --- | ---: | --- |
| 일반 | 36 | 공정별 문서 단어 수에 비례, EDS는 3 고정. 기본·상세 섞기, 여러 문장에 걸친 인과 질문 8개 이상 |
| 용어변형 | 9 | EDS / 웨이퍼 테스트 / 프로브 테스트, CMP / 화학적 기계적 연마 / 평탄화, 감광액 / 포토레지스트 / PR |
| 답없음 | 5 | 코퍼스에 없는 사실 (특정 회사 수율, 최신 장비 가격 등) |

일반 36문항의 공정별 목표예요. 처음에는 단어 수에 그대로 비례해 나눴는데, EUV lithography 문서 하나(10,550단어)가 포토를 11문항으로 끌어올렸어요. 그래서 배분 계산에서 문서 하나는 최대 3,000단어로 세기로 했어요([D-012](/fab-atlas/notes/decisions/#d-012--평가셋-일반-문항-배분-문서당-3000단어-상한)). 그다음 공정마다 최소 3개는 두기로 해서, 모든 공정에 3개씩 먼저 주고 남은 12개를 비례로 나눴어요([D-013](/fab-atlas/notes/decisions/#d-013--평가셋-일반-문항-공정별-최소-3개)). EDS는 3 고정이고, 소수점은 최대 나머지법으로 정리해요.

| 방식 | 웨이퍼 제조 | 산화 | 포토 | 식각 | 증착·이온주입 | 금속배선 | EDS | 패키징 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 단어 수 비례 (버림) | 3 | 3 | 11 | 2 | 8 | 2 | 3 | 4 |
| 문서 수 비례 (버림) | 5 | 3 | 5 | 5 | 6 | 3 | 3 | 6 |
| 문서당 3,000단어 상한 후 비례 (D-012, 대체됨) | 5 | 3 | 7 | 3 | 8 | 2 | 3 | 5 |
| **공정별 기본 3 + 나머지 12 비례 (D-013, 채택)** | **5** | **4** | **5** | **4** | **6** | **4** | **3** | **5** |

스모크 질문 Q1\~Q10은 재사용하지 않아요.

#### `check` 결과

- 빈 파일: 0문항, 문제 0건
- 포토 `draft` 시연으로 3문항(E001\~E003, drafted_by=claude)을 넣은 뒤: 일반 3/36, 인과 2/8, level 기본 1·상세 2, 원문 베낌 의심 0, 문제 0건, claude 초안 3개 남음

### Day 3 (10/25) 평가셋 검수와 9조합 실험

#### 검수 기준과 반영

판정 기준: 오류 = 기술적으로 잘못된 진술, 조건부 = 핵심 취지는 맞지만 일반화·조건 누락, 경미 = 표현 또는 정밀도 개선

정답은 근거 구절이 받쳐 주는 범위 안에 둬요. 근거 원문과 부딪히면 질문을 바꿔 근거와 맞추고, 근거 밖 지식은 note에 남겨요.

| 문항 | 판정 | 반영 |
| --- | --- | --- |
| E005 | 오류 | 원문이 "짧은 파장일수록 흡수 증가"라는 일반화를 담고 있어, 화학 증폭(S007 Chemical amplification) 질문으로 교체 |
| E007 | 조건부 | "2012년 한 리소그래피 전문가의 추정"임을 밝힘 |
| E015 | 오류 | 원문의 'bias'(언더컷 거리)가 업계의 식각 바이어스(식각 전후 CD 차이)와 달라, 바이어스 정의를 묻지 않게 질문 변경 |
| E026 | 오류 | "유전율이 1에 가까운 재료" → SiO₂보다 낮은 재료 + 다공성·공기 간극으로 유효 유전율을 낮춤 |
| E035 | 오류 | "TSV면 인터포저가 필요 없다"를 정답에서 빼고, 연결 길이·밀도 이점만 남김. S022 도입부를 근거에 추가 |
| E040\~E042 | 오류 | "종료점 신호가 없다"는 단정 → "종료점을 정확히 판단하기 어려울 수 있다". 과도한 연마는 "재작업이 어렵거나 폐기" |

그 뒤 50문항을 모두 읽고 그대로 승인했어요.

#### 검수 기록: `reviewed_by`

초안을 쓴 사람(`drafted_by`)과 검수한 사람(`reviewed_by`)을 나눠 적어요. 초안은 모두 claude가 썼고, 검수는 모두 내가 했어요. `check`의 목표는 "검수 안 된 문항 0"이에요.

```bash
uv run python scripts/eval_tool.py check    # 작성: claude 50 / 검수 안 된 문항 0 / 문제 0건
uv run python scripts/eval_tool.py format   # 에디터가 여러 줄로 펼친 파일을 한 줄 형식으로 정리
```

#### 9조합 실험: 청킹 3종 × 검색 3종

```bash
uv run python scripts/run_eval.py   # 결과: data/eval/results/2026-10-25_qa_v1.json
```

- 검색: dense(bge-m3, 한국어 질문 그대로) / BM25(영어 번역 후, D-011) / 하이브리드(RRF, k = 60, [D-014](/fab-atlas/notes/decisions/#d-014--하이브리드-검색-rrf로-순위-합치기))
- 정답 판정: 상위 5개 청크 중 하나라도 정답 근거(doc_id + 원문 글자 범위)와 겹치면 맞힘. 답없음 5문항은 빼고 45문항으로 Recall@5를 내요. 1문항이 2.2%p예요.
- 질문 임베딩과 번역은 질문마다 한 번만 만들어 9조합이 같은 값을 써요.

| 청킹 (청크 수, 평균 단어) | dense | BM25 (번역) | 하이브리드 |
| --- | ---: | ---: | ---: |
| section (296, 180) | 0.889 | 0.956 | 0.978 |
| w300o50 (219, 287) | 0.733 | 0.978 | 0.978 |
| w500o100 (140, 463) | 0.778 | 1.000 | 0.956 |

관찰:

- 번역+BM25는 청킹과 상관없이 0.956\~1.000으로 천장에 붙었어요. 하이브리드도 0.956\~0.978이에요. 이 범위의 차이는 1\~2문항이라 우열을 말하기 어려워요.
- dense만 청킹에 따라 크게 흔들렸어요. section 0.889, w300o50 0.733이에요. 기본으로 고른 w300o50(D-007)이 dense에서는 가장 낮았어요.
- w500o100에서는 하이브리드(0.956)가 BM25(1.000)보다 낮았어요. RRF가 dense의 틀린 순위를 섞어 넣은 경우예요(E005, E016).
- 용어변형: "EDS"로 물은 E037도 대부분 조합에서 찾았어요. 질문의 다른 말("불량", "표시", "걸러내")이 단서가 된 것 같아요. 이 묶음은 용어 차이만 시험하기에는 질문 맥락이 강해요.
- 평가셋이 BM25에 유리했을 가능성: 질문을 근거 구절을 보고 썼고, 번역 질의의 내용어 중 평균 50%(중앙값 50%, 최소 11%)가 근거 구절에 그대로 있었어요. 비교 기준이 없어서 단정하지는 않아요.

#### 편향 점검: 근거를 보지 않고 쓴 질문 (qa_blind)

qa_v1은 근거 구절을 보고 쓴 질문이라 BM25에 유리했을 수 있어요. 그래서 내가 원문을 보지 않고 질문 30개를 쓰고(`data/eval/qa_blind.jsonl`, 1차 12개 + 2차 18개), Claude가 질문을 다 쓴 뒤에 `find`와 직접 읽기로 근거를 붙였어요. 근거가 있는 문항이 24개, 답없음이 6개예요(식각 발전 방향, 인·붕소 비율, 수율 높이는 법, 2.5D, AI, 공정 간 결함 전파).

실험 전에 정한 판단 기준: BM25 − dense 격차가 qa_v1의 절반 이하로 줄거나 뒤집히면 "평가셋 작성 방식이 BM25에 유리했다", 비슷하면 "이 조합에서 BM25가 실제로 강하다".

```bash
uv run python scripts/run_eval.py --eval data/eval/qa_blind.jsonl
```

Recall@5 (근거가 있는 24문항, 1문항 = 4.2%p):

| 청킹 | dense | BM25 (번역) | 하이브리드 | BM25 − dense (qa_v1 → blind) |
| --- | ---: | ---: | ---: | --- |
| section | 0.625 | 0.500 | 0.542 | +6.7%p → −12.5%p |
| w300o50 | 0.542 | 0.417 | 0.583 | +24.5%p → −12.5%p |
| w500o100 | 0.667 | 0.542 | **0.708** | +22.2%p → −12.5%p |

- 세 청킹 모두 격차가 뒤집혔어요(−12.5%p, 3문항 차이). 정해 둔 기준으로는 "qa_v1의 작성 방식이 BM25에 유리했다"예요.
- 모든 검색기가 함께 떨어졌어요. qa_v1에서는 0.733\~1.000이었는데 blind에서는 0.417\~0.708이에요. qa_v1은 절대 성능도 높게 잡았어요.
- blind에서는 하이브리드가 세 청킹 중 두 곳에서 가장 높았어요(w500o100 0.708이 전체 최고).
- 번역 질의의 내용어가 근거 구절에 그대로 있는 비율: qa_v1 평균 50%, blind 평균 32%
- 1차(7문항)와 2차(17문항)는 결과가 달랐어요. 1차는 BM25가 0.143으로 극단적으로 낮았고, 2차만 보면 BM25 0.529\~0.706, dense 0.588\~0.647로 비슷했어요. 1차 질문이 더 넓고 일반적이었어요.
- 한계: 1문항이 4.2%p라, 하이브리드와 dense의 차이(1\~2문항)는 우열로 보기 어려워요. 질문 작성 방식과 질문 난이도의 효과가 여전히 섞여 있어요.
- 정답·근거 검수 뒤 다시 돌린 결과(`--tag reviewed`): B002·B017·B022·B023의 근거를 고쳤어요. BM25가 w300o50 0.417 → 0.500, w500o100 0.542 → 0.583으로 바뀌었고, 나머지 조합은 같아요. BM25 − dense 격차는 −12.5 / −4.2 / −8.3%p로 줄었지만 세 청킹 모두 여전히 뒤집혀 있어요. 바뀐 문항은 근거를 넓힌 B022, 그리고 같은 프롬프트(v1)·온도 0인데 번역 문장이 달라진 B018이에요.
- 번역 오역: "배선 공정"이 "wiring process"로 번역됐어요. 업계 표준어는 Metal Interconnect / Metallization이라 오역으로 판정했어요. BM25는 이 문항(B006)을 모든 청킹에서 놓쳤어요.
- 답없음 6문항 중 B007(수율 높이는 법), B030(결함 전파)은 흩어진 단서는 있어요. 단서를 모아 답하는 건 다음 단계로 두고, 지금은 답없음으로 판정했어요.
- 보고 방식은 [D-015](/fab-atlas/notes/decisions/#d-015--본-평가-보고-두-평가셋을-나란히-싣는다)로 정했어요. qa_v1에는 "근거를 보고 쓴 질문 기준" 꼬리표를 달고, qa_blind와 나란히 실어요.

#### 번역 프롬프트 v2: 표준 용어 매핑

blind에서 "배선 공정"이 "wiring process"로 오역된 걸 보고, 번역 프롬프트에 한국어 표현 → 업계 표준 영어 용어 매핑(`fabatlas/terms.py`)을 넣었어요([D-016](/fab-atlas/notes/decisions/#d-016--번역-프롬프트-v2-표준-용어-매핑)). 평가셋에 맞춰 늘리면 그 평가셋 점수가 부풀어서, 매핑 출처는 8대 공정 이름, 코퍼스 문서 23개 제목, 용어사전으로만 정했어요. dense는 번역을 쓰지 않아서 결과가 같아요.

```bash
uv run python scripts/run_eval.py --eval data/eval/qa_v1.jsonl --tag termmap
uv run python scripts/run_eval.py --eval data/eval/qa_blind.jsonl --tag termmap
```

| 평가셋 · 청킹 | BM25 v1 → v2 | 하이브리드 v1 → v2 |
| --- | --- | --- |
| qa_v1 · section | 0.956 → 0.933 | 0.978 → 1.000 |
| qa_v1 · w300o50 | 0.978 → 0.933 | 0.978 → 0.956 |
| qa_v1 · w500o100 | 1.000 → 1.000 | 0.956 → 0.956 |
| blind · section | 0.500 → 0.417 | 0.542 → 0.583 |
| blind · w300o50 | 0.417 → 0.458 | 0.583 → 0.667 |
| blind · w500o100 | 0.542 → 0.667 | 0.708 → 0.750 |

- B006(배선)은 세 청킹 모두 BM25로 찾게 됐어요. 다만 이 문항은 매핑을 넣게 된 계기라, 이 1문항의 개선은 평가셋에 맞춘 효과가 섞여 있어요.
- 그 밖에는 얻은 문항과 잃은 문항이 섞였어요(1\~3문항). 프롬프트가 바뀌면서 매핑과 상관없는 문장 부분까지 번역이 달라졌어요(qa_v1 39/45, blind 21/24문항). 그래서 매핑만의 효과를 따로 떼어 보기는 어려워요.
- 순수한 개선이라고 말할 근거는 아직 없어요. B006을 빼면 blind BM25는 section −3, w300o50 ±0, w500o100 +2문항이에요.

매핑 표현이 들어간 문항만 따로 봤어요("웨이퍼 → wafer"는 거의 모든 질문에 있어 뺐어요).

| blind 청킹 | BM25 매핑 문항 (16) | BM25 매핑 없는 문항 (8) | 하이브리드 매핑 문항 (16) |
| --- | --- | --- | --- |
| section | 7 → 6 | 5 → 4 | 9 → 9 |
| w300o50 | 9 → 9 | 1 → 2 | 11 → 12 |
| w500o100 | 9 → 11 | 4 → 5 | 11 → 12 |

- 매핑 없는 문항도 ±1문항씩 움직였어요. 변화는 대부분 번역 문장이 달라진 흔들림이에요.
- B006을 빼면 매핑 문항의 BM25 변화는 −2, −1, +1문항이에요. qa_v1의 매핑 문항(40)도 39→38, 39→38, 40→40이었어요.
- D-016의 다시 볼 조건에 해당해서 v1로 되돌렸어요([D-017](/fab-atlas/notes/decisions/#d-017--번역-프롬프트는-v1로-되돌린다)). v2 프롬프트, 매핑, 결과 파일은 기록으로 남겨요.

## 4. 결정과 이유

- [D-011](/fab-atlas/notes/decisions/#d-011--bm25-축-전용-질의-번역): 번역은 BM25 축에만 쓰고, 번역 모델은 답변 모델과 같은 gpt-4.1-mini 스냅샷으로 고정해요.
- [D-012](/fab-atlas/notes/decisions/#d-012--평가셋-일반-문항-배분-문서당-3000단어-상한): 평가셋 일반 문항은 문서당 3,000단어 상한을 두고 공정별 단어 수에 비례해 나눠요. 배분 방식은 D-013으로 대체했어요.
- [D-013](/fab-atlas/notes/decisions/#d-013--평가셋-일반-문항-공정별-최소-3개): 공정마다 일반 문항 최소 3개, 남은 12개는 단어 수 비례로 나눠요.
- [D-014](/fab-atlas/notes/decisions/#d-014--하이브리드-검색-rrf로-순위-합치기): 하이브리드는 dense와 BM25 순위를 RRF(k = 60)로 합쳐요.
- [D-015](/fab-atlas/notes/decisions/#d-015--본-평가-보고-두-평가셋을-나란히-싣는다): 본 평가는 qa_v1(근거를 보고 쓴 질문 기준)과 qa_blind를 나란히 보고해요.
- [D-016](/fab-atlas/notes/decisions/#d-016--번역-프롬프트-v2-표준-용어-매핑): 번역 프롬프트에 표준 용어 매핑을 넣어요. 매핑 출처는 8대 공정·문서 제목·용어사전으로 제한해요. → D-017으로 대체
- [D-017](/fab-atlas/notes/decisions/#d-017--번역-프롬프트는-v1로-되돌린다): 매핑 문항만 봐도 개선이 없어 번역 프롬프트를 v1로 되돌려요.
- [D-018](/fab-atlas/notes/decisions/#d-018--청킹-기본값을-w500o100으로-바꾼다): blind 세트에서 세 검색기 모두 가장 높았던 w500o100을 청킹 기본값으로 둬요(D-007 대체).
- [D-019](/fab-atlas/notes/decisions/#d-019--기본-검색기는-하이브리드rrf): 6조합 중 4곳에서 1등 또는 공동 1등인 하이브리드(RRF)를 기본 검색기로 둬요.

## 5. 막힌 점과 해결

### 평가셋 검수는 기술보다 도메인 지식이 필요했다

50문항 정답을 검수하는데, 배경지식이 부족해서 맞는 진술인지 판단하기 어려웠어요. 그래서 판정 기준(오류 / 조건부 / 경미)을 먼저 정하고, 근거 구절을 하나씩 번역해 읽고, 다른 LLM의 검토 의견을 참고했어요. 최종 판정은 내가 했어요. 정답은 근거 구절이 받쳐 주는 범위 안에서만 쓴다는 규칙도 세웠고, 그 결과 8문항을 고쳤어요(오류 7, 조건부 1). 도메인 지식이 평가셋 품질을 정하고, 이 부분이 기술보다 따라 하기 어려운 해자일 수 있다고 느꼈어요.

### BM25가 너무 잘 나와서 의심했다

qa_v1에서 BM25가 0.956\~1.000으로 거의 만점이었어요. 질문을 근거 구절을 보며 써서, 번역 질의 내용어의 50%가 근거에 그대로 있었어요. 근거를 보지 않고 질문 30개를 쓰고 그중 근거가 있는 24개로 다시 재니 겹침이 32%로 줄고, BM25와 dense의 우열이 뒤집혔어요. 평가셋을 어떻게 만드느냐가 결론을 바꿀 수 있다는 걸 배웠어요. 그래서 두 평가셋을 나란히 보고하기로 했고(D-015), 6조합 중 4곳에서 1등 또는 공동 1등인 하이브리드를 기본 후보로 두고 실패 사례로 확인하려고 해요.

## 7. 면접 한 문장

처음 만든 평가셋에서 BM25가 거의 만점(0.956\~1.000)이라 오히려 의심했고, 근거를 보지 않고 질문 30개를 쓰고 그중 근거가 있는 24개로 다시 재니 BM25와 dense의 우열이 세 청킹 모두 뒤집혔습니다. 그래서 두 평가셋을 나란히 보고하고, 편향이 적은 쪽을 기준으로 500단어 청킹과 하이브리드 검색을 기본값으로 정했습니다. 코퍼스가 바뀌면 기본값도 작은 평가셋으로 다시 골라야 하고, 그 평가셋의 정답은 도메인 전문가와 함께 검수해야 한다고 봅니다.
