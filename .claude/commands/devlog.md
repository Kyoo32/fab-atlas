오늘 작업을 FabAtlas 작업일지로 정리해요. CLAUDE.md 규칙(공개 안전, 저작권, 내 말로 쓰기, 문서화 예산)을 따라요.

## 1. 변경 읽기

- `web/src/content/docs/notes/devlog/`에서 가장 최근 작업일지의 `dateEnd`(없으면 `date`)를 찾아요.
- 그 날짜 이후의 `git log --stat`, `git diff`(스테이징 안 된 변경 포함), 새 파일(`git status`), `notebooks/*.ipynb` 변경을 읽어요.

## 2. 한 번에 묻기

아래 다섯 가지를 **한 메시지로** 물어요. 따로따로 묻지 않아요.

1. 오늘 결정한 것
2. 막힌 점
3. 새로 만난 용어
4. 면접 한 문장
5. 실제 쓴 시간(시간 단위 숫자)

오늘 작업이 이어 쓸 기존 주제가 무엇인지(또는 새 주제인지)도 같은 메시지에서 확인해요.

답이 비어 있는 칸은 비워 둬요. 내 답을 지어내거나 부풀리지 않아요.

## 3. 작업일지 초안

작업일지는 **작업 주제 단위**예요.

- 오늘 작업이 기존 주제의 연속이면 새 파일을 만들지 않아요.
  - 그 파일 `## 3. 과정`에 `### Day N (MM/DD) 소주제` 소절을 추가해요.
  - `dateEnd`를 오늘로, `hours`를 누적 시간(기존 값 + 오늘)으로 갱신해요.
  - 목표, 용어, 결정, 막힌 점, 숫자, 다음 할 일은 기존 섹션에 이어 써요. 내가 쓴 문장은 고치지 않아요.
- 새 주제면 새 파일을 만들어요: `web/src/content/docs/notes/devlog/YYYY-MM-DD-slug.md` (시작일, slug는 $ARGUMENTS 또는 작업 내용에서 영어 소문자로)
  - frontmatter에 `sidebar: { order: N }`을 넣어요. N은 기존 작업일지 order의 최댓값 + 1이에요.
- 기존 문서에 Day를 추가할 때는 `sidebar.order`를 바꾸지 않아요.
- 연속인지 새 주제인지 애매하면 나에게 물어요.
- `templates/devlog.md` 순서를 그대로 따라요: 목표와 완료 기준 → 새 용어 → 과정(Day별, 명령어·코드 포함) → 결정과 이유 → 막힌 점과 해결 → 숫자 → 면접 한 문장 → 다음 할 일 → `> 한 줄 정리:`
- 내부 링크는 `/fab-atlas/notes/...` 형식이에요. 파일을 합치거나 옮기면 `web/astro.config.mjs`의 `redirects`에 옛 주소를 추가해요.

## 4. 용어사전

- 새 용어는 `templates/glossary-entry.md` 형식으로 `glossary.mdx`의 알맞은 섹션("AI·검색" 또는 "반도체 도메인")에 추가해요.
- 반드시 `초안` 배지를 붙여요. 이미 있는 항목, 특히 배지가 없는 항목은 고치지 않아요.

## 5. 결정 기록

- 결정이 있으면 `templates/decision.md` 형식으로 `decisions.md` 맨 아래에 다음 번호(D-00N)로 추가하고, 작업일지에서 링크해요.
- 결정 번호는 결정한 시간순이에요. 같은 날 여러 개면 실제로 결정한 순서대로 매겨요.
- 공개 후에는 번호를 다시 매기지 않아요. 바뀐 결정은 새 번호로 추가하고, 옛 결정에 "→ D-00N으로 대체"를 달아요.

## 6. 진행 현황

- 완료된 항목이 있으면 `web/src/data/progress.json`의 `done`을 `true`로 바꾸고 `updated`를 오늘 날짜로 바꿔요. 애매하면 나에게 물어요.

## 7. 공개 안전 점검

- 이번에 바뀐 모든 파일과 제안할 커밋 메시지에서 회사명, 회사 서비스, 사내 시스템·프로젝트, 이직·지원 계획·회사·일정, 개인 연락처가 없는지 확인해요.
- 발견하면 빼고, 무엇을 뺐는지 나에게 알려요.

## 8. 빌드 확인

```bash
cd web && npm run build
```

실패하면 고친 뒤 다시 빌드해요.
