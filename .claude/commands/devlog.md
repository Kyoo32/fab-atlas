오늘 작업을 FabAtlas 작업일지로 정리해요. CLAUDE.md 규칙(공개 안전, 저작권, 내 말로 쓰기, 문서화 예산)을 따라요.

## 1. 변경 읽기

- `web/src/content/docs/notes/devlog/`에서 가장 최근 작업일지의 `date`를 찾아요.
- 그 날짜 이후의 `git log --stat`, `git diff`(스테이징 안 된 변경 포함), 새 파일(`git status`), `notebooks/*.ipynb` 변경을 읽어요.

## 2. 한 번에 묻기

아래 다섯 가지를 **한 메시지로** 물어요. 따로따로 묻지 않아요.

1. 오늘 결정한 것
2. 막힌 점
3. 새로 만난 용어
4. 면접 한 문장
5. 실제 쓴 시간(시간 단위 숫자)

답이 비어 있는 칸은 비워 둬요. 내 답을 지어내거나 부풀리지 않아요.

## 3. 작업일지 초안

- 파일: `web/src/content/docs/notes/devlog/YYYY-MM-DD-slug.md` (오늘 날짜, slug는 $ARGUMENTS 또는 작업 내용에서 영어 소문자로)
- `templates/devlog.md` 순서를 그대로 따라요: 목표와 완료 기준 → 새 용어 → 과정(명령어·코드 포함) → 결정과 이유 → 막힌 점과 해결 → 숫자 → 면접 한 문장 → 다음 할 일 → `> 한 줄 정리:`
- frontmatter의 `hours`에는 내가 답한 시간을 넣어요.
- 내부 링크는 `/fab-atlas/notes/...` 형식이에요.

## 4. 용어사전

- 새 용어는 `templates/glossary-entry.md` 형식으로 `glossary.mdx`의 알맞은 섹션("AI·검색" 또는 "반도체 도메인")에 추가해요.
- 반드시 `초안` 배지를 붙여요. 이미 있는 항목, 특히 배지가 없는 항목은 고치지 않아요.

## 5. 결정 기록

- 결정이 있으면 `templates/decision.md` 형식으로 `decisions.md` 맨 아래에 다음 번호(D-00N)로 추가하고, 작업일지에서 링크해요.

## 6. 진행 현황

- 완료된 항목이 있으면 `web/src/data/progress.json`의 `done`을 `true`로 바꾸고 `updated`를 오늘 날짜로 바꿔요. 애매하면 나에게 물어요.

## 7. 공개 안전 점검

- 이번에 바뀐 모든 파일과 제안할 커밋 메시지에서 회사명, 회사 서비스, 사내 시스템·프로젝트, 이직·지원 계획·회사·일정, 개인 연락처가 없는지 확인해요.
- 발견하면 빼고, 무엇을 뺐는지 나에게 알려요.

## 8. 빌드 확인

```bash
cd web && npm run build
```

실패하면 고친 뒤 다시 빌드해요.

## 9. 커밋 제안

- 커밋 메시지를 제안만 해요. 예: `devlog: 2026-10-13 코퍼스 수집`
- 커밋과 push는 내가 확인한 뒤에 해요.
